# 3. 어떻게 학습시켰나

모델을 고른 다음 실제로 학습시키면서 부딪힌 것들입니다.
**여기 적힌 설정은 대부분 "그냥 그렇게 했다"가 아니라 "다르게 했다가 깨져서 이렇게 됐다"입니다.**

---

## 소리를 숫자로 바꾸기

오디오는 그냥 파형(초당 16,000개의 숫자)입니다. 모델에 그대로 넣지 않고 **로그-멜 스펙트로그램**으로 바꿉니다.

```
10초 wav (160000,)  →  로그-멜  →  (프레임, 멜채널) 2차원
                                    가로 = 시간, 세로 = 음높이
```

사람 귀가 낮은 음의 차이에 민감하고 높은 음은 뭉뚱그려 듣는 성질(멜 스케일)을 반영한 변환입니다.
이렇게 하면 소리가 **사진처럼** 생긴 데이터가 되고, CNN이 잘 다루는 형태가 됩니다.

이 변환은 학습할 때마다 하면 느려서 **미리 계산해 `.npy`로 저장**해둡니다.

## 라벨은 멀티핫

한 클립에 유해가 하나만 있으라는 법이 없습니다. 총성 + 욕설이 같이 나올 수 있습니다.
그래서 라벨은 "정답 하나"가 아니라 **클래스마다 0/1**인 벡터입니다.
여기 이해가 잘 안된다면 one-hot-encoding을 찾아보세요.

```python
[1, 0, 1, 0]   # 비명 O, 타격 X, 총성 O, 욕설 X
```

채택된 소리 갈래는 폭력 4종(`vio_scream` / `vio_impact` / `vio_gunshot` / `vio_verbal`)이고,
폭력이 아닌 클립은 **네 자리가 전부 0인 네거티브 샘플**입니다
(negative = "유해 아님". 사람 목소리를 뜻하는 "음성"이 아닙니다).
따라서 마지막 층은 softmax(하나만 고르기)가 아니라 **클래스별 sigmoid**입니다.

---

## 부딪힌 문제들

### ① 유해 클립이 너무 적다

전체 8,648클립 중 폭력 양성은 일부입니다. 그냥 학습시키면
모델이 "전부 무해"라고만 답해도 정확도가 높게 나옵니다. 그리고 실제로 그렇게 됩니다.

**해결 두 가지:**
- **focal loss** — 이미 잘 맞히는 쉬운 샘플의 비중을 낮추고 어려운 샘플에 집중 (γ=2)
- **BalancedBatchSampler** — 배치를 만들 때 양성이 최소 몇 개는 들어가도록 강제

### ② 배치를 크게 못 쓴다

GPU 메모리 한계로 무거운 백본(BEATs/CED)에서는 배치 8이 최대였습니다.
근데 배치가 작으면 학습이 불안정합니다.
(가벼운 `conv` 백본을 쓰는 범용 설정 `configs/train/train.yaml`은 배치 32 × 누적 2입니다.)

**해결: gradient accumulation** — 배치 8을 4번 돌려서 기울기를 모았다가 한 번에 업데이트.
메모리는 8인데 효과는 32입니다.

```python
loss = loss / accum_steps      # 나눠주는 걸 잊으면 학습률이 4배가 됨
loss.backward()
if (step + 1) % accum_steps == 0:
    optimizer.step()
    optimizer.zero_grad()      # 여기서만 비움
```

### ③ fp16으로 학습하니 NaN이 떴다

메모리를 아끼려고 16비트로 학습했더니 손실이 NaN이 됐습니다.
fp16은 표현 범위가 좁아서 큰 값이 넘쳐버립니다.

**해결: bf16.** 정밀도는 fp16보다 낮지만 **표현 범위가 fp32와 같습니다.**
채택된 학습 스크립트는 전부 bf16으로 고정돼 있습니다.
(주의: `src/training/config.py`의 기본값은 아직 `fp16`입니다 — 범용 파이프라인을
BEATs 같은 무거운 백본으로 돌릴 거면 직접 bf16으로 바꿔야 합니다.)

### ④ 같은 영상의 조각들이 학습/평가에 나뉘어 들어갔다

한 영상에서 10초씩 여러 클립을 잘라냈는데, 그 조각들이 학습셋과 평가셋에 섞여 들어가면
모델이 "그 영상을 외운" 것만으로 평가 점수가 높게 나옵니다. **데이터 누수**입니다.

**해결: `source_id`(원본 영상 ID) 단위로 split.** 같은 영상에서 나온 클립은 통째로 한쪽에만 들어갑니다.

### ⑤ 좋아 보이던 체크포인트가 사실 운이었다

검증셋의 폭력 양성이 74개뿐이라, 몇 개 맞고 틀리는 것만으로 점수가 크게 흔들렸습니다.
그 흔들리는 점수로 "제일 좋은 체크포인트"를 골랐더니 사실 운 좋은 에폭을 고른 것이었습니다.

**해결:** 흔들림이 적은 val-AP로 기준을 바꾸고, 최종 비교는 **부트스트랩**으로 신뢰구간까지 냅니다.
두 모델의 차이가 신뢰구간 안에서 0을 포함하면 "차이 있다"고 말하지 않습니다.

### ⑥ 증강을 켰더니 총성이 나빠 보였다

데이터를 인위적으로 늘리는 **증강(augmentation)** 은 보통 잘 통하는 기법입니다.
파형 단계에서 볼륨 바꾸기·시간 밀기·노이즈 섞기·두 소리 겹치기(mixup)를 켜봤습니다.

결과: 총성 recall이 **0.633 → 0.449**로 떨어졌습니다.

**해결: 껐습니다.** (증강 코드는 `src/datasets/augment.py`에 그대로 있고,
채택 경로에서 `AUGMENT=0`으로 꺼둔 상태입니다. `AUGMENT=1`로 켜볼 수 있습니다.)

**여기서 정직해야 할 부분이 두 개 있습니다.**

1. **네 가지를 한꺼번에 켰습니다.** 그래서 "mixup 때문"이라고 말할 근거가 없습니다.
   짧고 날카로운 소리가 겹치면 뭉개진다는 건 **그럴듯한 가설**이지, 이 실험이 보여준 게 아닙니다.
   범인을 지목하려면 하나씩 끄고 켜는 **ablation**을 따로 돌려야 합니다.
2. **단일 시드입니다.** 시드를 바꾸면 점수가 얼마나 흔들리는지를 이 조건에서는 재보지 않았습니다.
   그러니 −0.184가 진짜 효과인지 우연인지도 엄밀히는 모릅니다.

확실한 건 **"켤 이유를 못 찾았다"** 까지입니다.
유명한 기법이라고 항상 맞지는 않고, "아니다"라는 결론도 제대로 세우려면
**한 번에 하나만 바꾸고, 시드를 여러 개 돌려야 합니다.** 이게 이 프로젝트가 아직 못 지킨 부분입니다.

## 파인튜닝 방식 — 전부 학습시키지 않는다

BEATs나 CED는 이미 AudioSet(200만 클립)으로 학습된 모델입니다.
우리 데이터 8,648개로 전체를 다시 학습시키면 **원래 알던 걸 잊어버립니다.**

그래서:
- 백본은 **위쪽 4개 블록만** 풀고 나머지는 얼립니다.
- 학습률도 다르게 줍니다 — **머리(새로 만든 부분) 1e-4, 백본(원래 있던 부분) 1e-5.**
  새로 만든 부분은 아무것도 모르니 크게, 이미 아는 부분은 살살.

## 지식 증류 — 큰 모델의 답을 베끼기

1층 게이트를 만드는 방법입니다. 정답 라벨만 보고 배우는 게 아니라
**선생 모델이 낸 확률까지** 따라 하게 합니다.

```
손실 = 1.0 × soft (선생 확률 따라하기, T=2)
     + 1.0 × cosine (선생의 중간 표현 방향 따라하기)
     + 0.3 × hard (진짜 정답 라벨)
```

"정답은 폭력"보다 "폭력 0.7, 기타 0.2"가 정보가 더 많습니다.
선생이 헷갈린 정도까지 배우는 셈입니다.

중간 표현 따라하기는 처음에 MSE로 했다가 실패했습니다.
손실값이 0.008로 너무 작아 다른 항에 묻혀버렸거든요. **cosine(방향만 비교)으로 바꿔서 해결**했습니다.

## 양자화

학습이 끝난 뒤 가중치를 32비트 실수 → 8비트 정수로 바꿉니다.

```
0.73621845...  →  0.74   (256단계 중 하나로 반올림)
```

재학습이 필요 없고(PTQ), 이 프로젝트에서 측정한 성능 손실은 폭력 트리거 기준 **통계적으로 0**이었습니다.
경량화 지렛대 중 가장 값싼 것입니다.

실제 줄어든 배율은 이론값 4배가 아니라 모델마다 다릅니다 — 가중치만 정수로 바뀌고
다른 부분은 그대로이기 때문입니다.

| 모델 | 줄어든 정도 |
|---|---|
| CED-mini 39MB → 10MB | 3.8배 |
| BEATs 364MB → 106MB | 3.4배 |
| KoELECTRA 56MB → 28MB | 2배 (단어 임베딩 표가 fp32로 남음) |

## 12시간마다 끊기는 환경에서 학습하기

무료 GPU는 세션이 강제 종료됩니다. 그래서 **중단은 예외가 아니라 정상 상황**으로 취급합니다.

- 매 에폭 체크포인트 저장 (모델 + 옵티마이저 + 에폭 번호 + 랜덤 시드 상태)
- `--resume auto` — 재시작하면 마지막 체크포인트에서 이어서
- 11시간 지나면 스스로 저장하고 종료 (12시간에 잘리기 전에)
