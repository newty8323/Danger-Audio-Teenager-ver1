# 1. 이 프로젝트가 푸는 문제

## 한 줄 요약

**소리만 듣고, 지금 재생 중인 콘텐츠가 청소년에게 유해한지 판단한다.**

영상의 화면을 보지 않습니다. 마이크로 들어오는 소리, 또는 폰이 재생 중인 소리만 씁니다.

## 왜 소리인가

화면을 캡처해서 분석하는 방식은 두 가지가 걸립니다.

1. **사생활** — 화면에는 메신저 대화, 사진, 비밀번호까지 다 들어옵니다.
2. **전력** — 화면을 계속 캡처해서 이미지 모델에 넣으면 배터리가 못 버팁니다.

소리는 정보량이 훨씬 적고, 그래서 훨씬 작은 모델로 훨씬 적은 전력으로 돌릴 수 있습니다.
대신 소리만으로는 알 수 없는 것도 있습니다 — 그 한계는 [05-limits.md](05-limits.md)에 적어뒀습니다.

## 무엇을 유해로 보는가

| 분류 | 어느 갈래가 맡나 | 예시 |
|---|---|---|
| 폭력 | **소리** | 총성, 비명, 유리 깨지는 소리, 타격음, 폭발 |
| 도박 | **말/텍스트** | 베팅 관련 표현. 슬롯 소리는 신호가 약해 소리 갈래에서 뺐습니다 |
| 성적 | (보류) | 윤리 제약상 원본 오디오 미수집 — [05-limits.md](05-limits.md) |
| 유해 발화 | **말/텍스트** | 욕설·위협·혐오 표현 |

처음엔 도박도 소리로 잡으려 했습니다. (슬롯머신 릴, 코인 소리 같은 것)
그런데 **소리만으로는 신호가 너무 약했습니다** 그리고 카지노 효과음은 게임·예능에도 그대로 나옵니다.
그래서 도박은 말 갈래로 옮겼고, 모아둔 도박 클립은 **"유해 아님" 예시(네거티브 샘플)** 로 재활용했습니다.
지금 소리 갈래는 **폭력 전용**입니다.
(제가 이렇게 구성한 것이지, 여러분이 바꿔도 무방합니다.)

출력은 "유해 / 무해"의 O·X가 아니라 **정도(%)** 입니다.
같은 총소리라도 뉴스 보도와 잔인한 게임 실황은 다르게 취급해야 하기 때문입니다.

## 전체 구조 — 3층 캐스케이드

핵심 아이디어 하나만 기억하면 됩니다.

> **항상 도는 모델만 작으면 된다. 가끔 도는 모델은 커도 된다.**

배터리를 먹는 건 모델 크기가 아니라 **모델 크기 × 도는 빈도**입니다.
그래서 모델을 하나 만드는 대신, 세 층으로 나눠서 뒤로 갈수록 크고 정확하되 덜 자주 돌게 했습니다.

```
┌─ 1층: 상시 게이트 ────────────────────────── 24시간 계속 돔
│  0.32M 파라미터 (증류로 만든 초소형 CNN)
│  질문: "볼 만한 소리가 나긴 했나?"
│  놓치면 안 되니까 recall 위주 — 오경보는 많아도 됨
└──────────────┬───────────────────────────────
               │ 뭔가 들렸을 때만 깨움
┌─ 2층: 트리거 ─────────────────────────────── 가끔 돔
│  소리 갈래: CED-mini int8 (10MB) — 폭력음 탐지
│  말  갈래: Moonshine-KR (ASR) → KoELECTRA-small int8 (28MB) — 유해 발화 탐지
│  질문: "유해가 의심되나?"  → 예/아니오
└──────────────┬───────────────────────────────
               │ 의심될 때만 서버로
┌─ 3층: 서버 ───────────────────────────────── 아주 가끔
│  Qwen2.5-Omni (소리 + 텍스트를 같이 이해하는 큰 모델)
│  질문: "이게 얼마나, 어떤 맥락으로 유해한가?"  → 정도(%) + 근거
└──────────────────────────────────────────────
```

1층이 걸러주기 때문에 2층은 하루 종일 돌 필요가 없고,
2층이 걸러주기 때문에 서버는 정말 의심스러운 몇 초만 보게 됩니다.

### 설계 규칙 하나

게이트(1층)와 트리거(2층)를 **같은 데이터로, 비슷한 놓침 비율로** 학습시키면
둘을 이어 붙여도 **전체 놓침이 트리거 혼자일 때와 거의 같아집니다.**
층을 쌓았다고 성능이 층 수만큼 깎이지 않게 하는 조건입니다.

## 소리가 들어오는 두 가지 경로

| 경로 | 설명 | 1층 게이트 |
|---|---|---|
| ① 외부 마이크 | 폰 마이크로 주변 소리를 들음 | **필요** (언제 소리가 날지 모름) |
| ② 기기 내 재생음 | 폰이 재생 중인 유튜브·게임 소리를 직접 캡처 | **불필요** — OS가 "재생 중"인지 알려주므로 그게 공짜 게이트 |

②가 훨씬 유리합니다. 음질이 깨끗하고, 학습에 쓴 데이터(유튜브 원본)와 소리 성질이 정확히 같기 때문입니다.
①은 스피커 → 공기 → 마이크를 거치며 소리가 변해서(울림·거리), 그 상황에서도 잘 되는지는 아직 검증 전입니다.
